# CB-001 — ChisaBot release path

- Date: 2026-10-14
- Status: in review
- PR: placeholder

## Requirements

ChisaBot (`ChisaAlter/ChisaBot`, default branch `main`) must be able to cut and publish a release
without a workflow job that only runs on `CopilotKit/OpenBot`.

- Create-release and publish workflows run for this repository.
- Images and packages the publish workflow pushes are owned here. The name is
  `ghcr.io/chisaalter/chisabot`, with component images
  `ghcr.io/chisaalter/chisabot-<service>`.
- Authentication stays on `GITHUB_TOKEN`. No new secrets.
- Production VPS updates keep building `local/chisabot` from `main`. This run does not switch that
  updater to GHCR.
- PC and Android installers keep shipping from `.github/workflows/release.yml` on `v*` tags.

## Plan

1. Replace the `github.repository == 'CopilotKit/OpenBot'` gates with `ChisaAlter/ChisaBot`. Do not
   leave an `or` that still allows the upstream repository.
2. Rename the create-release concurrency group from `openbot-release-pr` to `chisabot-release-pr`.
3. Point every publish tag, attestation subject, and `container-images.json` repository at
   `ghcr.io/chisaalter/chisabot`. Keep the manifest key `openbot` so existing `jq` examples still
   read `.images.openbot`.
4. Point the Helm chart default and the release docs at the same registry.
5. Accept `chisabot-<harness>` as an installed plan harness image, alongside the local Compose tag
   `openbot-<harness>`.
6. Have **Create release PR** create the `release` label when it is missing, because publish trusts
   that label and this repository did not have it.

## Outcome

The two upstream gates are gone. Merging a reviewed `release/publish/vX.Y.Z` pull request that
carries the `release` label publishes container images for this repository and opens the GitHub
Release with `GITHUB_TOKEN`.

## Remaining manual steps

- The `chisaalter` organization must allow GitHub Actions to create packages. After the first
  publish, set visibility on `ghcr.io/chisaalter/chisabot` and each
  `ghcr.io/chisaalter/chisabot-<service>` if the packages are created private.
- No container image exists for the current v0.1.6 GitHub Release. Those assets are client
  installers. The first container publish is a new release cut from Actions.
- Windows desktop signing still uses CopilotKit's Azure federated credential in
  `desktop/signing/azure-federation.json`. It is not part of the container publish path.
- `renovate.json` still extends `local>CopilotKit/renovate`. Renovate is not a workflow job and was
  left unchanged.
