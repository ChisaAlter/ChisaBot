# 连续办公验收：依赖与数值复核补修

CB-087 的滚动、队列和执行控制修复已由 PR #283（`6bcb7656`）上线。正式 Web 连续 15 条消息完成，长命令、一次执行、Stop、跨刷新/另端持久暂停与显式单条恢复均通过；独立产物验证继续发现办公和代码问题，因此增加后续补修。

## 已复现

- 实际计算机 shell 的 `import openpyxl` 失败。机器人转为手工拼 OOXML，文件中的五类明细和公式正确，但打印了硬编码的错误汇总 24,800 / -1,200，并把该数字写进 Word。后续 Python 对同一明细算出正确 26,200 / +200，最终总结仍沿用了旧说法。
- 下载的 Python CLI 对文件编码明确，但没有配置 stdout/stderr。Windows 原生非 UTF-8 子进程运行时，中文输出不是 UTF-8，严格解码失败。仅在提示里泛化建议不够，必须要求检查实际交付文件。

## 补修

- 主镜像和好友镜像安装发行版 `python3-openpyxl`、`python3-docx`，构建时真实 import 断言。不改 shell 环境，不在运行中的生产容器临时安装；Dockerfile 变化由现有指纹触发完整镜像构建，后续代码更新继承依赖。
- 共用指导要求使用文档库、重新读取已保存行、计算独立总和，对所有依赖文档使用同一真实数据；不把硬编码打印当核验，不把写公式当已经计算缓存。
- 可下载 Unicode CLI 的启动代码明确配置 stdout/stderr；以非 UTF-8 环境启动实际文件，父进程严格 UTF-8 解码中文正常输出和中文错误，未通过先修正再分享。
- `tests/office-runtime-smoke.py` 在非 root 的独立镜像中真实创建/重开 XLSX 与 DOCX，验证公式、明细及 26,000 / 26,200 / +200 一致。
