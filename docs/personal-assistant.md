# 用 ChisaBot 办事

在聊天里交代目标，在任务详情里看成果；需要日历、邮箱或随身提醒时，再连接对应服务。无需为了基本文件操作安装额外 coding agent。

本页说明个人助理候选的使用方式。当前部署、构建版本和实际验收状态见[实施记录](pipeline-runs/20261108-assistant-production.md)；正在实施的命名清理与0067迁移见[迁移说明](ops/upstream-removal.md)。

## 先办一件有明确成果的事

可以直接在聊天里说：

> 根据我上传的两份材料整理项目待办，区分已经确认和仍待确认的事项，给我一份可下载的 Markdown 报告，并列出依据。

需要持续执行或分步骤跟进时，从右栏「任务」进入「任务中心」，选择「新建任务」。在「目标与交付标准」写清输入材料、允许操作的目录、要交付什么；执行方式可选已有的「ChisaBot 机器人」。

在任务详情的「计划与成果」打开实际文件或结果；「执行日志」和「执行轨迹」用于查看卡在哪一步。只有总结文字不等于文件已交付，必须能打开对应成果。设备离线、工具被拒或结果待核对时，先处理该原因，不反复点击重试。

任务的「暂停」「继续执行」「取消任务」管理该任务；聊天中的停止按钮只针对当前回合。已经发生的文件写入或外发不会因停止而撤销。

如果原对话出现「这一步的结果需要你核对」，先打开目标服务或文件查看实际结果，再选择「操作已经完成」「操作没有执行」或「操作未完成」，填写核对说明。选择「记录并继续」后，机器人根据这份结果继续，不会再次执行原操作；原任务已停止或对话已经变更时，只记录结果。历史查询等只读操作失败会直接返回错误，不需要核对外部效果。

## 日历、邮箱和通知只在安全表单中连接

打开「账号与设置 → 账号连接」，在「全部」或「连接」中找到「日程、收件箱、通知推送与每日晨报」。

- **连接日历**：填入 ICS/WebCal 订阅地址或 ICS 内容，设置日历时区。没有声明时区的日程按该设置解释；日历为只读，不会修改原日程。
- **连接邮箱**：使用应用专用密码或客户端授权码连接 IMAP，读取邮件标题、发件人、时间和未读状态，不读取正文或附件。需要发信时勾选「配置并验证 SMTP 发信连接」，填写服务商提供的服务器、465（TLS）或 587（STARTTLS）端口和用户名；SMTP 使用独立密码时可单独填写。验证只登录服务器，不发送邮件，实际发信为纯文本并按审批偏好确认。旧连接仍可读取收件箱，未经 SMTP 验证的连接会明确标示。
- **绑定通知推送**：填入你希望实际收到提醒的 Webhook。它是发给本人的提醒出口，与接收外部事件的入站 Webhook 不同。

私密订阅地址、Webhook 和密码只填这些表单，不发到聊天里。未连接的服务会显示未连接；模型不能据此知道你的日历或收件箱内容。

连接后可点「预览今日晨报」或「巡检动态」。结果中的来源时间和状态决定如何使用内容：

- 新鲜数据：本次读取成功；空列表才表示查询范围内没有结果。
- 缓存数据：本次未成功读取，显示的是上次成功内容及其时间。
- 不可用：本次读源失败，需要处理连接或稍后再试。
- 未连接：尚未授权该来源，不会用演示内容冒充真实数据。

## 设提醒前，先确认关闭客户端后送到哪里

例如：

> 明天上午九点，按北京时间提醒我核对项目清单。

在「设置 → 定时任务」核对时间、时区和下一次运行。关闭客户端不等于停止服务器任务；要停用已有提醒，请暂停或取消对应定时任务。

没有绑定本人通知目标时，不要把聊天内的记录理解为手机已经收到提醒。绑定后先向自己的目标发送一条明确的测试通知，确认实际收件，再依赖它。已有暂停任务不会因为更新自动恢复。

工作流的步骤审批、人工验收、完成和失败也会通过这个本人通知目标提醒。已经处理的审批或已经重试的旧结果不再发送；点击通知可回到对应工作流。

## 发邮件时，先看草稿，再看发送记录

把收件人、主题、正文要求说清楚，例如：

> 先拟一封邮件给我指定的收件人，主题为项目进度。先展示完整草稿，等我确认后再发送。

按当前审批偏好核对收件人和完整内容后决定。若修改对象或正文，重新核对。查看「账号连接 → 最近发送记录」：

- **平台已接受**：SMTP 或通知平台明确接纳；不等于收件人已读。
- **发送失败**：记录本次失败原因。
- **结果待核对**：请求可能已经产生效果，但未取得确定回执。先到收件端核对，不直接重发。

## 记忆要带条件，也能更正和忘记

> 记住：工作日整理会议记录时，先列待办，再列背景。

在「设置 → 记忆」查看实际保存的内容。需要改时说清楚新条件；需要忘记时点名原事实。更正后换一个会话核对是否按新要求处理，不把当前聊天仍能看到的旧文字当作长期记忆仍在使用。

## 遇到异常，保留原记录再处理

任务待批准时处理原审批卡；结果待核对时查原回执；模型不可用时查看主备模型提示。不要靠新建重复任务、连续重试或恢复旧数据库来消除不确定状态。

部署者可从[监控与巡检](ops/monitoring.md)查看 DSH、任务失败、未知效果、备份和证书信号；备份恢复与镜像兼容规则见[DSH 运维](ops/dsh-runtime.md)。
