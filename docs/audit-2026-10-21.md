## 四、测试套件

- 基线（纯净 HEAD，同目录实测）：**1151 通过 / 210 失败**。
- 现在：`bun run test:app` → 主进程 1346 通过 / 0 失败 + 8 个隔离文件全绿，**退出码 0**。

两件事值得记住：

1. **`bun test app/tests` 在旧写法下永远有 40~50 条假红。** Bun 的 `mock.module()` 是进程级的，
   `mock.restore()` 在 1.3.14 里换不回来（最小复现：A 文件 mock 一个模块，B 文件仍拿到替身；重注册真模块也无效），
   而测试文件的 import 在开跑前就解析完了。`approval-tools` / `turn-unfinished` 把
   `@copilotkit/react-core/v2` 整包换成替身之后，后面用真 SDK 的文件全崩。
   → 新增 `scripts/run-app-tests.ts`（`bun run test:app`）：**需要干净进程的文件各自一个进程跑**，
   名单在脚本里写明了原因（整包 mock / 改 document / 性能阈值）。往名单加文件前先想清楚：
   能改成 mock 局部缝的，就别隔离。
2. **一批"红"其实是测试自己坏了**：`onMutate` 是 async 却没 await、Windows 上 glob 返回反斜杠导致白名单从未命中、
   注册 happy-dom 后不注销（四个文件）。这些已经修掉。

## 五、非问题（查过，决定不动）

- **`/settings/pages` 预览里的一行 CSP 报错**：Cloudflare 在边缘往 `/p/` 的 HTML 注入 `beacon.min.js`，
