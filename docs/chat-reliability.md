# 聊天可靠性：滚动、暂停队列与请求期限

CB-087 修复连续办公和代码验收后保留的滚动、恢复与兼容问题，保持 CB-086 的命令只执行一次及真实取消行为。

## 用户看到的行为

- 新消息追加、流式结束、停止标记和备用模型提示变化时，已经显示的消息保持同一个节点，不重建历史。
- 回答结束后逐帧收回留白。慢帧不会一次追赶整段距离；上滑或新回答会保留当前高度，避免突然跳回。
- Stop、失败或服务重启后，未处理补话显示「已暂停 · 等待你发送」。刷新、另开页面或再发一条新消息都不自动处理旧暂停项。
- 点「发送这条」只发送所选补话；其他项继续暂停。可以撤回。后台任务结果也能暂停后显式读取。
- 超时与网络错误保留队列和已有记录；不因为未收到响应而自动再执行写操作。提交结果未知的补话也必须由服务端确认撤回，撤回预留终态可以拦住晚到的提交。
- 系统偏好减少动态效果时，发送直接延续底部，不制造整轮锚定的人工留白，也不平滑滚动。

## 实现

长对话的 tail-first 窗口在渲染前同步协调旧长度和新长度，使用第一条消息标识区分末尾追加与历史前插；48 条阈值和首次补齐期间也保留已挂节点。停止、备用模型等标记与消息保持平级 keyed children，避免条件嵌套数组改变父 fiber。末尾留白使用受限的每帧增量收回，慢帧不按墙上时间追赶。

服务端增加 `chisabot_thread_inbox_control`（thread_id、paused、updated_at）。暂停、晚到入队、认领和显式发送在控制行锁下串行；暂停项和近期终态分开取数，100 条完成记录不能遮掉新补话。普通新发送只打开未来排队，原暂停项继续保留。显式发送携带源 id 和新消息 id，由服务端原子认领并重新构造内容；旧页面携带暂停 id 不能绕过。删线程和机器人同时清理控制行。

通用 API 客户端把调用方取消信号与默认 30 秒期限组合，期限持续到响应正文消费。计算机命令、下载和审批调用提供较长独立预算。收件箱请求统一使用该传输层，格式错误按暂时不可用处理。

数据库保留 Bun SQL 和 Drizzle，增加 PostgreSQL 默认 `statement_timeout=25000`、`lock_timeout=5000`，连接 URL 参数可以覆盖。应用侧监督查询、池等待与事务提交阶段；超时或协议异常淘汰当前连接池，取消未完成工作并强制关闭旧连接。受影响请求失败，不重放查询或事务；新请求才使用新池。事务回调中的非数据库等待不计入单条数据库请求期限。

生成 Python 文件的共用指导要求明确文件、CLI stdout/stderr 及子进程双方编码；在非 UTF-8 环境验证下载的代码，不依赖线上 Linux 的 locale 推断 Windows 兼容。

- `app/tests/message-node-identity.test.tsx` 观察真正 DOM reference 与中间删除，涵盖追加、流式内容原地更新、失败、回放、标记、阈值、首次补齐和换频道。
