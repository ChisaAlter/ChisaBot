# 维护、备份与排错

[文档首页](README.md) · [部署说明](../deploy/README.zh-CN.md) · [模型配置](models.md) · [Magpie](magpie.md)

## 发布前与升级后

按部署说明备份数据库、凭据加密密钥及必要配置，记录当前镜像版本。构建并验证自己的 ChisaBot 镜像，使用版本或摘要固定发布；上游 ChisaBot 镜像不包含本分支全部中文、自托管和模型选择改动。

至少验证以下实际流程：

1. 未登录访问受保护页面跳转登录；登录和退出都生效。
2. 管理页面可读取连接配置，但不返回原始 API Key。
3. 模型目录可以加载并刷新，BOT 设置与聊天选择器同步。
4. 两个 BOT 使用不同模型，互不覆盖。
5. 发送实际消息成功，回复持久保存。
6. 重启后覆盖值和会话仍可读取，恢复默认不会改动其他 BOT。

不需要为验收把所有用户 BOT 改成同一个模型。需要修改测试 BOT 时，记录原覆盖值，验证后恢复，保留已有对话与账户配置。

## 需要保存的数据

| 数据 | 为什么要备份 |
| --- | --- |
| PostgreSQL | 对话、BOT 覆盖值、全局模型配置、加密凭据和审计 |
| `KEY_ENCRYPTION_KEY` | 读取原加密凭据需要原密钥，替换后不能自动解密旧数据 |
| 网页登录服务数据与私有配置 | 用户登录和会话由相应认证组件管理 |
| BOT 工作区与浏览器资料 | 文件与网页登录状态，不包含在数据库备份中 |
| Magpie 持久配置 | 供应商、账户、调用密钥和开放范围 |
| 镜像版本与反向代理配置 | 可重复恢复或回滚至已验证版本 |

这些内容存于自己的私有部署环境。Git 仓库保存代码、脱敏模板和说明，不保存密码、密钥、数据库导出、Cookie、浏览器配置文件或完整私人日志。

## 模型问题排查

先区分失败发生在哪一层：

| 失败位置 | 优先检查 |
| --- | --- |
| 打不开登录或应用 | 认证网关、应用健康、前端静态资源、浏览器错误 |
| 管理员无法读取/保存配置 | 登录角色、同源请求、数据库与凭据加密密钥 |
| 模型列表无法加载 | 保存的协议/地址/密钥、服务端到网关网络、`/models` 权限 |
| 新模型无法保存 | BOT 所有者/管理员权限、BOT 是否本地执行、模型是否在当前目录 |
| 保存正常但对话失败 | 实际模型 ID、上游授权、额度、工具/协议支持与服务状态 |

模型测试连接发起真实的短推理请求，可能消耗上游额度。其结果与目录加载、配置保存分别独立。不要通过保存按钮成功来判断上游模型已经可用。

目录请求被限制为 15 秒。目录接口出错时，旧缓存不会被替换为空目录，但失败的刷新仍报告错误；已有 BOT 覆盖值不会被自动删除。恢复默认不需要目录成功。

应用显示的错误使用安全分类。排查上游详细原因时，在自己的受保护管理界面检查对应请求的时间、模型 ID、HTTP 状态和用量，分享日志前删去密钥、认证头、Cookie、私人地址和对话内容。

## 迁移模型连接

更换协议或 API 地址时，应填写新连接的密钥或关闭密钥鉴权，不会自动将旧服务密钥发送到新地址。保存后，刷新目录并逐个检查有覆盖值的 BOT。

已有覆盖值不会因连接变更被清除。在新网关中找不到原 ID 时，可选择当前目录中的对应完整 ID，或恢复部署默认。正在进行的、已经解析连接的运行继续使用本轮快照。

## 遥测与外部能力

自托管并不自动关闭所有外部访问。按环境设置 `COPILOTKIT_TELEMETRY_DISABLED=true`、`DO_NOT_TRACK=1`，按需关闭联网插件及生成界面能力。`CHISABOT_GENERATIVE_UI=false` 可关闭可能从 CDN 加载库的生成界面功能。

当模型本身来自第三方 API，其推理请求会离开服务器；如需本地推理，接入自己运行的兼容模型服务。参见 [能力边界](chisabot.md)。
