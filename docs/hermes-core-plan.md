# ChisaBot 以 Hermes 为执行内核：复核意见与修订计划

状态（2026-10-21）：设计已进入实现与服务端隔离验收。宿主工具网关、Hermes 原生 ACP 适配器、完整历史/模型传递、取消和去重已实现；真实模型经实际 ChisaBot 工具网关读取公开网页并得到回执。尚待前端执行归属、完整工具名映射、更新器联动的最终验收和生产发布。以下原审查表记录的是实施前基线，不代表当前代码仍保留这些缺口。

## 1. 判断与目标

**Hermes 可以作为 ChisaBot 的目标执行内核，但当前桥接只是可运行原型，还不能算完整替换。**
先完成工具、身份、记忆、历史、模型设置等能力的保留与验证，再统一切换。当前资料不足以证明
“CopilotKit 的循环天然没有做事能力”或“Hermes 必然能解决消极回复”，不能把这两句话当迁移依据。

产品始终是一个连续的个人助理：对话、搜索、操作设备、调用连接器、持续任务共用同一身份和上下文。
不引入“聊天模式”和“任务模式”，不要求用户判断该用哪个内核。目标是所有自有 bot 统一使用
Hermes 执行循环；原实现只在迁移期作为验证基线和显式回滚手段，不做自动路由或静默降级。

核心替换的边界：

- ChisaBot 保留 bot 身份、账号授权、模型设置、持久历史、个人记忆、设备、文件交付、渠道、定时任务、权限偏好和 UI。
- Hermes 提供模型执行循环、过程内上下文管理、工具调度、任务推进与其适合复用的技能能力。
- Hermes 在服务端运行。用户的电脑操作继续通过已经授权的设备节点进行，无需在用户本机安装 Hermes。
- 工具与权限执行尽量复用现有实现，避免重造一套授权、确认、记忆或设备体系。

## 2. 审查依据及范围

本次重新直接阅读了下列代码。表中的事实来自代码，不代表这些功能在当前部署的每个 bot 上都已启用。

| 位置 | 观察 | 对设计的意义 |

| [copilot.ts](../server/src/copilot.ts#L1114) | Hermes 切换在 loadTools 前返回；传入空工具列表 | 当前集成主动绕开原能力，是需要修复的集成缺口 |
| [copilot.ts](../server/src/copilot.ts#L1205) | 普通 remote 路径不传个人长期指令；per-bot 模型解析也主要针对 built_in | 把 bot 数据行改成 remote 可能改变原有指令和模型语义 |
| [copilot.ts](../server/src/copilot.ts#L1643) | remote 路径传工具 schema 和签名 run；HeadlessToolsMiddleware 执行未回答工具并再次调用远端 | Hermes 工具结果与宿主工具续跑必须去重，避免重复执行 |
| [bridge.mjs](../examples/acp-agent/bridge.mjs#L253) | 只取最后一条用户文字；不消费完整消息、工具结果、附件和 resume | 工具续跑、重试、附件与历史恢复需要补齐 |
| [bridge.mjs](../examples/acp-agent/bridge.mjs#L296) | 会话按 threadId 保存在内存；session/new 的 mcpServers 为空；system 首轮 seed | 缺少完整身份键、持久映射及动态上下文同步 |
| [bridge.mjs](../examples/acp-agent/bridge.mjs#L505) | 仅对收到的 ACP permission 请求选择允许/取消 | 不能据此认定所有工具都受其控制 |

这轮额外只读检查了服务端 systemd：Hermes 桥 active，User/Group 未设置。也检索了已安装
Hermes 的 ACP 实现：命令审批通过 terminal 的危险命令审批回调接入 ACP；存在单独的编辑审批。
这说明 `ACP_APPROVAL=deny` 只会拒绝实际发来的权限请求，**不能当成 terminal 全禁用或只读沙箱**。

上一轮记录的镜像版本、5 个 bot 数据行和运行回执保留为历史快照。本轮未重新查询所有线上配置、
凭据、bot 数据或运行完整验收，不将旧快照当成当前完整健康报告。

## 3. 对上一版计划的纠正

1. **现有系统不是“没有环境和工具的薄聊天 agent”。** 已有搜索、浏览器、工作区、设备操作、记忆、技能、定时跟进等宿主能力。能力差需要查实际工具是否被装配、筛选、调用，以及循环如何终止。
2. **数据库 type 不等于实际执行内核。** 在全局 Hermes 开关下，built_in 也走 Hermes；不能说另外四个 bot 一定仍跑旧循环。星灵改成 remote 是临时配置方式，不是正式迁移方案。
3. **执行 date 只证明端到端通路可用。** 它没有验证连接器、个人记忆、用户设备、任务续跑、附件或重启恢复，更不能证明“主观能动性”问题已解决。
4. **个人助理统一体验不要求技术上立即删掉原实现。** 迁移期保留基线与回滚，产品里不做两个模式；失败时不得静默换脑。
5. **先完成能力保留，再迁移全部 bot。** 不能先把所有 bot 切过去，再补工具和审批。
6. **沿用用户权限偏好。** 不把每个 shell/file 操作都变成新的确认卡，也不把 deny 当沙箱。隔离、鉴权和实际工具拦截必须分别验证。
7. **不预设“全功能 4–6 周”等承诺。** ACP 动态工具、权限覆盖、模型设置、恢复能力需要先做验证；没有这些结果，工期与成功率数字缺少依据。

## 4. 当前集成缺口与优先级

| 级别 | 缺口 | 后果与处理 |
| --- | --- | --- |
| 阻止扩大迁移 | 工具装配被绕过，input.tools 未接入 Hermes | 连接器、记忆写入、用户电脑等能力可能回退；先接通工具执行 |
| 阻止扩大迁移 | 身份/工作区边界、服务账号与桥鉴权未完整建立 | 服务端命令可能碰到产品凭据；限制进程权限、挂载和调用范围 |
| 阻止扩大迁移 | 仅最后一条用户文字，无事件去重/恢复协议 | 重试或工具续跑可能重发用户请求，导致重复操作；定义消息游标与幂等 |
| 阻止完整替换 | 原有个人指令、模型设置未等价传递 | 用户设置变成无效或静默改变；保持产品设置为权威 |
| 阻止完整替换 | 记忆与人设只在 ACP 第一轮 seed | 后续记忆/授权/角色修改可能不生效；每轮同步必要上下文 |
| 阻止完整替换 | 线程映射只在内存且只用 threadId | 重启遗忘、跨 bot 同 thread 可能共享会话；使用完整身份键并持久化 |
| 阻止完整替换 | 附件与产物链未贯通 | 用户传图/文件及取回生成文件可能失败；接回原文件服务 |
| 质量问题 | ACP 事件部分丢弃，缺少端到端运行日志 | 难区分模型选择、工具拒绝、连接错误与桥转换错误 |

必须补测的并发与生命周期问题：同 thread 首次并发创建 session、同 run 重试、排队时用户停止、
子进程异常后的恢复、超时取消后工具是否继续执行，以及 HeadlessToolsMiddleware 续跑时结果能否
回到 Hermes。不能仅用“有 RUN_FINISHED”作成功判据。

## 5. 目标架构与契约

```text
网页 / 客户端 / IM / 定时任务
                │
          ChisaBot 服务端
     身份、bot、模型设置、记忆、历史、工具、文件
                │
       AgentRuntime 统一运行契约
                │
         HermesRuntimeAdapter
                │
       服务端 Hermes 执行循环
                │
        ChisaBot 工具适配接口
                │
   既有工具执行 / 设备 hub / 连接器 / 确认偏好
```

`AgentRuntime` 至少需要定义：

- 可信运行身份：owner/actor、bot、thread、run、触发来源；由服务端解析，不能采信模型自报。
- 运行输入：完整消息或可验证增量、长期指令、动态记忆、模型选项、工具目录、附件。
- 运行过程：消息/工具/进度事件、用户追加指令、确认请求、取消与超时。
- 运行结束：成功/失败/等待用户/取消、输出文件、用量、可恢复的会话句柄。
- 幂等：runId 与 messageId 去重，写入工具重试策略，工具结果与执行状态对齐。

ACP 可作为 Hermes 接入方式，但不是必须坚持的最终接口。先确认它能支持所需的动态工具、会话恢复、
模型设置与取消。如果有关键缺口，评估 Hermes 的 Python API/服务适配器；不为了保留通用桥而维护
第二套工具循环，也不把宿主设定长期塞成普通用户文字作为最终 prompt 管理方式。

### 工具适配的优先选择

1. 先梳理 /api/agent-tools/call 与 loadToolsForActor 的覆盖差异。
2. 提取一个可复用、身份绑定的工具执行入口，复用 grants、确认、停止信号和审计；HTTP 回调与原循环都调用它。
3. 若 Hermes ACP 的 MCP 支持足够稳定，用一个薄 MCP 适配器暴露既有工具；不复制工具实现。
4. 短期 run 凭据的续期、每轮工具目录刷新、MCP 会话重连必须一并处理，不能只在 session/new 塞一个即将过期的 token。
5. 持久会话不能共用一个全局可变 currentRun，否则并发时会把 A 用户的工具调用归到 B 用户。
6. MCP 执行回执与 AG-UI 展示事件对应同一个 toolCallId，防止宿主又执行一次。

### 数据与设置归属

| 能力 | 权威来源 | Hermes 的角色 |
| --- | --- | --- |
| bot 身份、用户长期指令 | ChisaBot | 每轮得到可信、可更新的配置 |
| 模型和推理设置 | 现有 ChisaBot 设置 | 适配后传递，无法支持时明确报错，不静默用全局模型 |
| 用户记忆、线程历史 | ChisaBot | 读取并按原工具规则写回；会话缓存可重建 |
| 执行摘要、临时文件 | Hermes 工作区 | 不能与其他 bot/用户混用；交付时进入 ChisaBot 文件服务 |
| 设备授权、连接器凭据 | 原服务 | 不向模型或 Hermes 暴露原始密钥 |
| 工具权限与确认偏好 | 原服务 | 尊重已有“完全访问”等设置；缺乏授权时请求确认 |

## 6. 分阶段实施与退出条件

### A. 建立基线与能力清单

任务：

- 记录同一模型下原 agent 与 Hermes 各自收到的 prompt、工具名、工具结果、终止原因；敏感值脱敏。
- 梳理 loadToolsForActor、computer 工具、回调 API、记忆、定时/IM 与文件交付的对应关系。
- 固定 Hermes commit、依赖版本和当前运行配置，明确服务端安装/更新来源。
- 为“连接 ima 先调查”复现原失败，区分工具筛选、描述、提示词、权限拒绝或循环提前结束。

退出条件：有能力矩阵、失败链路和代表任务记录；不再用 date 或 session 数替代任务验收。

产出：能力矩阵、脱敏 trace、接入方式验证结论。

### B. 验证 Hermes 接入并先建立运行边界

任务：

- 用服务账号/容器限制文件与进程权限，代码只读、workspace 可写；不依赖 cwd 充当隔离。
- 桥鉴权与 bot/user 运行身份建立关联；不把全局密钥塞进人设或 prompt。
- 验证 ACP 的 MCP 工具调用、model/config、session load、取消、权限覆盖、计划/进度事件。
- 验证用户电脑操作继续走设备节点，不落到服务器本机 terminal。

退出条件：得到是否继续 ACP 的明确结论；未授权进程不能读产品密钥，普通任务仍能工作。

若 ACP 无法完整承载上述能力，先调整 Hermes 适配器，而非继续扩展部署。

### C. 接通一个完整的个人助理能力闭环

任务：

- 完成工具执行公共入口，复用现有 /api/agent-tools/call 能力和工具装配。
- 先贯通搜索、连接器发现、记忆读写、一个设备只读操作、一个需确认的写操作。
- 使用真实 schema、实际调用结果和统一 toolCallId；保留工具拒绝/失败的区别。
- 对 Hermes 原生操作核对权限覆盖；未覆盖的能力通过 OS 权限或已受控执行后端限制。
- 确认后恢复时不重放已经执行的写操作，取消后不开新工具。

退出条件：同一个对话里，能调查服务、读取记忆、调用用户已授权工具、按偏好完成一个操作并回报结果。

### D. 保留连续性与现有设置

任务：

- 按 owner/bot/thread 绑定会话，持久化 session mapping；重启后 load 或幂等重建。
- 每轮同步长期指令、记忆、权限及工具目录变化；不重复追加整个历史。
- 保留 ChisaBot 模型选择及推理设置，明确 Hermes 不支持的选项。
- 处理同会话并发、消息重试、运行中追加指令、停止、断线重连。
- 图片、文件输入与生成文件交付接回现有服务；不支持的输入明确报错。
- 验证 IM、定时任务和后台作业，无网页在线也可执行并交付。

退出条件：重启不遗忘、设置修改下一轮生效、不同 bot 不串、图片和文件往返可用。

### E. 正式统一与部署

任务：

- 在 adapter 通过验证后，让自有 bot 默认使用 Hermes；外部第三方 agent 类型保留其原义。
- 不再把自有 bot 通过手改数据库伪装成任意 remote；用可迁移的正式 runtime 配置表达。
- 不新增“快问快答/任务”开关，也不要求用户按 bot 学两套内核。
- 将星灵临时 type/角色追加变更纳入正式迁移与回滚；原始人设与个人指令保持完整。
- 服务、依赖、配置、迁移与回滚纳入 GitHub 和既有 updater；不再靠生产目录手工补文件。
- 清理全局开关与特殊路径；原实现保留为发布回滚手段，后续确认无回归再删除。

退出条件：网页、客户端、IM、后台同一身份走同一 Hermes adapter；运行记录能明确证明实际内核。

## 7. 验收：任务完成与能力保留

所有任务均在相同模型、相同权限、相同初始数据条件下记录原实现与 Hermes 的表现。
只比较可核实的结果，不把工具调用次数或动手率当成完成率。

| 场景 | 成功证据 |
| --- | --- |
| “了解一下腾讯 ima 怎么接” | 实际检索并读资料，区分官方/第三方来源，给出凭据与接入步骤；不编造已连接 |
| “看看我有哪些连接器，能否访问某个知识库” | 使用当前账号和工具目录，返回真实授权状态；不猜测无权限 |
| “记住这个偏好，下次按这个做” | 原记忆服务有记录，下轮与桥重启后仍生效 |
| “在我电脑找某文件并读它” | 经既有设备节点执行，有设备标识；不在服务器寻找同名文件 |
| “整理文件并让我下载” | 产物真实存在，ChisaBot 文件卡能下载，内容正确 |
| “修改某条记录” | 尊重现有权限/确认偏好，只写一次；取消/拒绝无修改 |
| 对话中更新人设/模型 | 下一轮配置生效或明确指出不支持，不静默继续旧设置 |
| 桥重启、客户端重连、同 run 重试 | 上下文保留；无重复工具副作用 |
| 图片/PDF 输入 | 真正收到对应内容，或明确告知不支持；不装作看过 |
| 定时/IM 任务 | 无网页在线仍执行、按渠道回报，缺授权时准确等待/通知 |

必须通过的工程测试：身份隔离、未授权调用、动态撤权、工具幂等、取消、异常恢复、凭据脱敏。
性能记录首字时间、总耗时、模型请求数、token/费用；先测基线，再确定可接受阈值。

## 8. 回滚与执行约束

- 本审查稿不授权本轮直接更改生产内核或删除运行数据。
- 线上修改仍按 GitHub + 现有 updater；数据迁移必须有可逆记录。
- 出错时明确显示失败或等待，不能静默 fallback 后让用户误以为仍是 Hermes。
- 迁移回滚同时处理镜像、runtime 配置、bot 数据行和会话；恢复 type 但保留全局 Hermes 开关不算真正回滚。
- 不为本任务再在用户本机安装 Hermes；本地仓库只用于源码审查与开发。
