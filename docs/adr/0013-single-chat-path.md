# ADR-0013：机器人聊天只有一条路——频道聊天

- 状态：已采纳
- 日期：2026-10-15
- 相关：DESIGN.md §68、BACKLOG CB-046、ADR-0001（左栏只有机器人）、DESIGN.md §42 / §64

## 背景

机器人聊天有两套实现：`/channel/*`（`ChannelChat`，左栏点机器人进的，用户每天用）和 `/bot?agent=`（旧聊天前端框架 的 `旧内置聊天组件`，只有
定时任务提醒「查看」等少数入口进）。确认卡片、后台任务结果、回答期间插话、备用模型提示、历史对话、上传进工作区这些功能和它们的 e2e
大多先做在 `/bot` 上，用户真正用的频道聊天反而缺；两边的修复也在分叉（§64 的刷新续写就是在频道聊天上补的）。服务器上频道对话还被当成
「群聊」，拿不到委派和定时任务工具。用户 2026-10-15 08:04：「删掉旧的，继续精简。」

## 决定

- 频道聊天是唯一的聊天界面。`/bot` 只做跳转：有 thread → `POST /api/channels/open-thread`（找到或给它建频道，同一个 thread id，不复制
  消息）→ `/channel/<id>`；没有 → `/channel/new?agent=`。旧链接、书签、通知里的「查看」都继续能用。
- `/bot` 独有的功能搬进频道聊天，`/bot` 的渲染代码（`rich-message-view`、`message-list`、`bot-model-input` 等）删掉。
- 服务器按「频道里有几个机器人」区分：一个机器人的频道 = 和这个机器人聊天，给委派、定时任务、本地 agent；多机器人的群聊频道不给。
- 频道上传另存一份进机器人工作区 `uploads/`（和旧 `/bot` 一样），附件本身仍走频道附件表。
- `/api/bot-threads/*` 保留（频道聊天的同步戳和历史对话在用）。

## 后果

- 一套界面、一套 e2e；以后的聊天功能只做一次。
- 旧 `/bot` 对话第一次打开时会多一个频道（同一条对话），以后都打开这个频道。
- 旧聊天前端框架 v2 的 `旧内置聊天组件` 不再使用；它的样式表是否还需要见 DESIGN.md §68。
- 回滚：回到上一个镜像即可（没有表结构变化；open-thread 建的频道在旧版本里是普通频道）。
